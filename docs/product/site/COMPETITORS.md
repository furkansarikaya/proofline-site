## Implications for us

- GitHub Spec Kit uses the word "evidence" in its own pitch and ships bug fixing and idea assessment next to spec-driven development (C-70, C-71), so "evidence" alone no longer separates proofline; the site has to show how a verdict is enforced and by what, the gap its reviewers name (C-72).
- GitHub Spec Kit organises its home page by the job a reader has (C-79), which is a pattern for the proofline home page: "install it", "see why I can trust it", "read the guides".
- Superpowers is the closest skills-based methodology and its users praise correctness (C-74); its install is per harness (C-80), so a "works with Claude Code and Codex from one install" claim is a concrete difference proofline can show if it is true.
- awesome-claude-code is a list, not a rival; a listing in it and in similar directories is a way to reach the same readers and belongs on the launch checklist, not in the site.
- Cursor rules are instructions placed in the prompt, and Cursor staff say the agent sometimes ignores them (C-73); this is the demand for enforcement that proofline answers, and the site can name it without naming Cursor.
- Aider opens with usage numbers (C-78); proofline has one star today (RESEARCH C-23), so its first screen needs another kind of proof, such as what a run records.
- Claude Code, used plain, and Codex, used plain, remain the main alternative; the complaint that the agent jumps to implementation too early (C-75) is the problem statement for the home page, and both vendors publish an index file and Markdown pages for agents (C-76, C-77), which is now an expected feature of tool documentation.

## So what

- IN-8 Spec Kit already says "evidence" and offers verification-like processes, so the evidence pitch is shared ground. evidence: C-70, C-71, C-72; so what: positioning should lead with enforcement (what blocks a claim without proof), not with the word "evidence", and the "why I can trust it" page should show an enforced check.
- IN-9 Spec Kit's reviewers call the process heavy, and the plain agent's users say it rushes. evidence: C-72, C-75; so what: the home page can set proofline between the two, "a proof step without the paperwork", if the product earns that claim; this is a positioning option for the decision.
- IN-10 Cursor staff confirm that written rules are sometimes ignored. evidence: C-73; so what: the evidence page gains a concrete problem to answer, "instructions are not enforcement", and the information architecture should put that page one click from the home page.
- IN-11 Both agent vendors publish a documentation index for agents. evidence: C-76, C-77; so what: the documentation section of the site should publish an index file and Markdown versions of its pages as part of its scope.
- IN-12 Spec Kit organises by job, Aider opens with usage numbers, Superpowers installs per harness. evidence: C-78, C-79, C-80; so what: the home page structure should be job-led with a single install path for both agents, and it cannot lean on star counts yet.
