# Premortem: proofline site

<!-- "It is a year later and this failed. Why?" kind is real, overstated or unspoken. RK-1 to RK-3 are the product owner's stories; RK-4 to RK-12 were proposed by the agent. Ids AS-n point to ASSUMPTIONS.md, RESEARCH C-n to RESEARCH.md. -->

- RK-1 A visitor saw the full lists of roles, skills and gates on the first page, thought "this is too much for me" and left. kind: real; response: the home page tells only the shortest path (install it, run one task, see the proof); the full lists of roles and skills stay in the documents and are linked from the home page, not listed on it (AS-1, AS-10)
- RK-2 Proofline itself changed and the site fell behind: commands or the installation changed and the quick start on the site no longer works. kind: real; response: the install and quick-start commands on the site come from the same source as the documents, and the build compares them with the commands in the README and fails when they differ (AS-2, AS-7)
- RK-3 The name was confused: because other products carry the same name, a searcher went to another site or took proofline for that other product. kind: real; response: the descriptive phrase of RESEARCH C-60 is used everywhere and a page title never carries the name alone, in titles, descriptions and structured data (AS-13)
- RK-4 Visitors read proofline as Spec Kit with more steps, because the first screen used the same word "evidence" (COMPETITORS C-70), and the stars stayed flat. kind: unspoken; response: the first screen shows the difference before the word "evidence": a script blocks a claim that has no proof (ASSUMPTIONS C-94); once the design exists, a probe shows the first screen to a few developers who know Spec Kit and asks what differs, with the product owner's go (AS-10); source: agent accepted by user
- RK-5 The key of the traffic snapshot job leaked and gave write power over the main repository. kind: unspoken; response: the key is a fine-grained personal access token with the narrowest permission, limited to the proofline repository and to reading the traffic only; the permission it needs is confirmed in the technical design from the GitHub documentation; the job runs only on its schedule or by hand and never on a pull request (RESEARCH C-87); source: agent changed by user
- RK-6 The traffic snapshot job stopped silently, because the key expired or the scheduled job was paused, and a gap in the short GitHub history was lost for good (ASSUMPTIONS C-95). kind: unspoken; response: every run updates a "last snapshot" date in the saved file, and the site build warns when that date is older than the schedule allows (AS-12); source: agent accepted by user
- RK-7 The document sync showed wrong information: the site is pinned to one commit (RESEARCH C-61), the repository moved on and the site shows old commands, or an automatic pull request carried pages that break the build. kind: unspoken; response: every document page shows the commit or tag it was taken from, a sync pull request cannot merge before the build check passes, and the pin moves to the tag when tags exist (RESEARCH C-62) (AS-11); source: agent accepted by user
- RK-8 Links inside the proofline repository still lead to the old site addresses and break. kind: unspoken; response: the old site itself does not matter (RESEARCH C-82), but a link in the README or the documents of the proofline repository that leads to an old address is fixed; the search on 2026-11-19 found no such link in the 1529 text files of the repository, and the repository's homepage field points to the domain root, which stays valid; the search is repeated before the launch; source: agent changed by user
- RK-9 The Turkish pages went out of date and nobody saw it, because the translation check only warns. kind: unspoken; response: every Turkish guide page reads the existing "translated-from" header line (RESEARCH C-27) and shows which version of the English source it follows, with a visible notice when the English source has moved on, without failing the build (AS-15); source: agent accepted by user
- RK-10 The ownership check never worked. The DNS record was late or never added, the fallback meta tag is printed only when its variable is set (RESEARCH C-83), and the site looked verified while Search Console had no data. kind: unspoken; response: the launch checklist includes checking the verification status in Search Console by hand, and the build log says "verification tag: present" or "absent" without printing the value (AS-6); source: agent accepted by user
- RK-11 Visibility for the descriptive queries never came and nobody measured it; only stars were watched and the site stayed a copy of the README. kind: unspoken; response: eight weeks after the launch the Search Console impressions for the descriptive queries are read and compared with the query-to-page table of RESEARCH, and the content is changed when they are absent (AS-8, RESEARCH C-84); source: agent changed by user
- RK-12 The trust page did not convince the team lead: it held claims without a record that can be checked. kind: unspoken; response: the trust page links to the proof page and the CI results that the README already points to (docs/proof.md), and the technical design checks that those links stay valid (AS-9); source: agent accepted by user
