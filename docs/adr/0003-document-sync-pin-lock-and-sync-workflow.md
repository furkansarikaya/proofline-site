# 0003. Fetch the pinned documents at build time against a lock, transform them deterministically, and move the pin by a GITHUB_TOKEN pull request

Status: accepted
Date: 2026-11-19

## Context

FR-9 to FR-15, NFR-7, AC-15 to AC-19 and AC-34 define the synced set, the pin, the link rules, the Markdown surface and the sync pull request. The user asked for "sabitlenmiş commit'in belgelerini build sırasında alan bir script; bağlantıları site adreslerine çeviren, eşitleme kümesi dışındakileri GitHub adresine döndüren, Türkçe kılavuzları da alan, deterministik". Q-5 (b), (h), (m) and the Codex-text and red-sync parts of (p) are open. FR-4, AC-3, AC-8 and AC-9 also read the README of the pinned commit, which is not a synced page. Evidence tree at the candidate pin 457729b31481a8a1915c06ec3bddd57b549f0194: 50 synced files, link targets of all shapes, placeholders such as `<slug>` that CommonMark parses as raw HTML, 56 shared-rules comments, GFM tables, YAML frontmatter in every SKILL.md.

## Decision

1. Pin: `sync/pin.json` = `{"commit": "<40 hex>", "tag": null | "vX.Y.Z"}`. The commit is the truth; the tag is a label shown on pages (AC-17).
2. Lock: `sync/lock.json` lists every synced file and every read-only input (`README.md`) with path, git blob id and sha256, plus `tree_sha256`, the sha256 of the sorted `path<TAB>type<TAB>blob` listing of the whole archive (needed to resolve out-of-set links). The build downloads `https://codeload.github.com/furkansarikaya/proofline/tar.gz/<commit>`, verifies the extracted file contents (not the archive bytes, whose compression is not promised to be stable) against the lock, caches under `.cache/sync/<commit>/` (git-ignored) and fails on any difference, naming the path. Documents are not committed to the site repository.
3. Determinism: inputs sorted by path, no clock, no network except the pinned archive (and the non-output snapshot status read of ADR 0007), sitemap without `lastmod`, build identity = pin. CI builds twice and compares a hash of `dist/` (ADR 0008).
4. Synced set = FR-9 globs as one exported constant with a test: `docs/guides/*.md`, `docs/guides/tr/*.md`, `docs/concepts/*.md`, `docs/proof.md`, `docs/limits.md`, `skills/*/SKILL.md`. Links are mapped by resolved repository path: in the set -> site address (anchor kept, `.md` dropped, Turkish files -> `/tr/docs/guides/...`); not in the set but present in the archive -> `https://github.com/furkansarikaya/proofline/blob/<commit>/<path>` (`/tree/` for a directory); absent -> build fails naming source file, line and link (AC-18). Absolute URLs untouched. Fragments into synced pages are checked and only warned (AC-18 fails only on a missing target). Heading ids with github-slugger so GitHub-style anchors keep working. Images (none at the pin) become a link to the GitHub blob of the image, never an `<img>` to another host (NFR-1).
5. Transform and sanitization (NFR-7), mdast based and independent of Astro's processor: split YAML frontmatter with `yaml`; parse with remark-parse + remark-gfm; read the `translated-from` comment; then turn every `html` node (block and inline) into a `text` node with the same literal value, except HTML comments, which are dropped; links with a scheme other than `http`, `https` or `mailto` become text; render with remark-rehype (no `allowDangerousHtml`) and rehype-stringify; no syntax highlighting (inline `style=` would break the CSP of ADR 0006). The post-build scan (ADR 0008) fails on `<script`, `<iframe`, `<object`, `<embed`, `<style` inside synced content, any `on*=` attribute and any `javascript:` URL. Fixture test: `<script>alert(1)</script>`, `<img src=x onerror=alert(1)>`, `[x](javascript:alert(1))`, and `<slug>` must render as visible text.
6. Markdown surface (Q-5 b, FR-15, AC-34): `/llms.txt` at the root, linked from `/docs/` and `/tr/docs/`, lists every synced page with title and Markdown address. The Markdown of a synced page is at the page address with `.md` (`/docs/guides/daily-use.md`, `/tr/docs/guides/gunluk-kullanim.md`); content = upstream text with only link targets rewritten, offset-based on mdast positions (comments kept as upstream wrote them, because Markdown is not rendered by the site); served `text/markdown; charset=utf-8` with `nosniff` (vercel.json). Site-written pages get no Markdown version in v1 (revisit at the FR-30 evaluation). The checker verifies each listed address exists in `dist/`, and the browser run requests each with status 200 through `scripts/serve-dist.mjs`.
7. Facts extracted from the pin, never typed (Q-5 m, AC-8, AC-9, Codex part of p): from the whitespace-collapsed plain text of the first paragraph of `docs/proof.md`, `Figures\s+were\s+taken\s+on\s+(\d{4}-\d{2}-\d{2})\s+at\s+proofline\s+(\d+\.\d+\.\d+)`; the link to the H2 `What this does not prove` uses its github-slugger id; from the README section `## Status`, the exact sentences `It is not yet proven on real projects.` and `/Codex as implementer is supported \([^)]*\); other Codex roles are not yet verified in real use\./`. English pages render the extracted sentence; the Turkish pages carry a hand-written translation that depends on the same guard. The version is never read from the README (it states two). If any sentence, figure or heading is missing, the BUILD FAILS naming the page and the pattern. FR-4: the README range from `## Install` to `## What it supports` is read from the same archive; command lines of fenced blocks are compared after trimming and removing a trailing ` #` comment; inline command spans of the get-started page are compared only when the page marks them as commands (a `Command` component), so "starts with a command" is explicit, not guessed.
8. Sync workflow `.github/workflows/sync.yml`: triggers `schedule` (weekly) and `workflow_dispatch` (input `commit`, optional). One long-lived branch `sync/proofline` and at most one open PR, updated in place by force-push when a newer target is due; a manual dispatch overrides a tag-follow target. Tag-follow (AC-19): among tags matching `v<semver>`, the highest version whose compare status `pin...tag` is `ahead`; the API is called with the job's GITHUB_TOKEN as bearer (shared runner IPs make the 60/h anonymous limit unreliable). The job runs `npm ci` and `npm run build` before it opens or updates the PR; the PR body lists added, removed and changed files from the lock diff. A red build opens or updates the PR as DRAFT with the log tail and label `sync-red`, and the body carries a ready-made upstream issue text that the maintainer files in the proofline repository by hand; the live site stays on the old pin because nothing merges. PR creation uses the default GITHUB_TOKEN with `permissions: { contents: write, pull-requests: write, issues: write }` and the repository setting "Allow GitHub Actions to create and approve pull requests", which the sync workflow task turns on (owner decision; the repository is public). The CI run of that PR starts in the approval-required state: the maintainer's "Approve workflows to run" click is the review point (Q-5 h). The branch ruleset requires the check of ADR 0008.

## Alternatives considered

- Vendoring (committed copies of the documents): reviewable diffs in the PR, but the user asked for fetch-in-build, the copies can be hand-edited and drift from the pin, and every sync rewrites up to 50 files. Rejected.
- git submodule: brings the whole repository, no lock of the synced set, Vercel and CI need submodule checkout, and the rewriting script is still needed. Rejected.
- GitHub contents API per file: 50+ requests per build, rate limits, and a token in every build. Rejected.
- PAT or GitHub App token for the sync PR so CI starts without approval: a long-lived write credential in the repository, against NFR-8 and RK-5. Rejected.
- Dispatching CI from the sync job: checks of a `workflow_dispatch` run do not appear on the PR and do not satisfy a required check (G2). Rejected.
- Rendering synced Markdown with Astro's own processor and stripping raw HTML: the processor's raw-HTML behavior is not stated (A1), and stripping deletes visible placeholders such as `<slug>`. Rejected.

## Consequences

- The build needs network access to codeload.github.com (CI, Vercel); an outage fails the build visibly instead of publishing stale pages. The cache keeps local rebuilds offline.
- The sync PR shows the lock diff, not the text diff; the reviewer follows the GitHub compare link in the PR body for the text.
- One upstream defect (a missing link target or a reworded trust sentence) keeps every later sync red until upstream fixes it; this is the intended NFR-4 behavior.
- PRD wording (owner): FR-11 and AC-15 say the PR "changes the pin and the synced pages/documents": here it changes `sync/pin.json` and `sync/lock.json`. FR-14 says the `translated-from` lines "render": they are comments, read and dropped. NFR-7 says raw HTML is "removed": here it is escaped as visible text. NFR-4 gains one failing condition (missing trust sentence, figure or heading; the owner may downgrade it to a warning, at the cost of AC-8).
- Confidence medium on point 8: the approval-required state of a GITHUB_TOKEN PR must be seen once on a real sync PR (sync workflow task).
